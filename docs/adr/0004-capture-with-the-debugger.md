# Capture the tab through chrome.debugger, so it can be in the background

_Supersedes [ADR-0003](0003-capture-with-activetab.md)._

A long Chat Record takes minutes, and with `chrome.tabs.captureVisibleTab` the WhatsApp Web tab had to stay the visible tab of its window throughout: Chrome captures only the active tab, stops painting a hidden one, runs no animation frames there and slows its timers to about once a second, so switching tabs or minimising the window failed the run. It also needed a toolbar click per tab load for the `activeTab` grant. We now capture with the `debugger` permission: for exactly one Chat Record the background worker attaches `chrome.debugger` (protocol 1.3) to the WhatsApp tab, turns on `Emulation.setFocusEmulationEnabled`, and captures with `Page.captureScreenshot` (`fromSurface: true`), then detaches. Verified in Chromium (Playwright's build, a real extension): a tab hidden behind another tab, in a minimised window or under another window still captures correct, freshly scrolled pixels (about 20 to 70 ms each, no rate limit); with focus emulation it reports `visibilityState` `visible`, runs about 120 animation frames a second and unthrottled timers, so WhatsApp Web keeps rendering and the extension's waits keep their pace. Detaching ends the emulation. The session lives as long as a port from the content script, so reloading or closing WhatsApp Web detaches too.

`<all_urls>` would also have removed the toolbar click, but `captureVisibleTab` still captures only the visible tab, so it doesn't let the tab go to the background, and it asks for every site. `activeTab` keeps the click and the visible-tab limit.

Accepted costs:

- **The permission warning.** Chrome warns at install that the extension can "Access the page debugger backend" and read and change data on all websites: `chrome.debugger` can attach to any tab, although this extension only attaches to the WhatsApp Web tab that asked, for the length of one Chat Record.
- **The debugging bar.** While attached, Chrome shows "WhatsApp Assistant started debugging this browser" across the top of its windows. Clicking its Cancel detaches the debugger and fails the run, keeping a Partial Chat Record. The bar resizes the page as it appears and can stay a while after detaching (it was still there 4 s after a detach in Chromium), so the Camera waits for the viewport to settle before a run measures the chat area, and every capture checks the chat area has not moved (a run fails cleanly instead of cutting screenshots in the wrong place).
- **WhatsApp Web believes it is visible and focused** during a run, even in a background tab. That is how it behaved before (the tab had to be visible); for example it may send read receipts for a Chat open during the run.
- **Clipboard.** Chrome checks focus when the clipboard write starts, which is still inside the Create click, so a PNG finished while the user is in another tab is still copied (verified in Chromium).
